# acne-care: 피부 사진 기록·비교 웹앱

> 초기 팀 프로젝트 acne-CV를 개인 프로젝트로 발전시켜, 피부 사진 분석부터 촬영일별 기록 관리·비교·리포트까지 구현했습니다.

- 형태: 바이오헬스 캡스톤 개인 프로젝트이며, 후속 개발 전체를 직접 수행했습니다.
- 담당 범위: 기존 코드 조사, 데이터 검사·라벨 보완, 모델 학습·평가, 백엔드와 웹 화면 구현을 담당했습니다.
- 기술: Python, PyTorch, Ultralytics YOLO11n, FastAPI, SQLite, HTML, CSS, JavaScript를 사용했습니다.
- 원본 저장소: [acne-care](https://github.com/hhjhhjh/acne-care)에서 코드와 실험 기록을 확인할 수 있습니다.
- 시연 자료: [시연 영상](https://youtube.com/shorts/VC3mpvTDcXo)에서 사용 흐름을 확인할 수 있습니다.

## 문제와 목표

초기 [피그널·acne-CV](acne-cv.md)는 5인 팀으로 얼굴 이미지의 피부 트러블을 탐지하고 부위별 결과와 과거 기록을 보여주는 프로토타입이었습니다. 이후 같은 사람의 사진을 촬영일별로 보관하고, 여러 기록의 탐지 위치와 개수를 비교할 수 있도록 서비스 범위를 확장했습니다.

후속 개발에서는 데이터와 모델의 평가 근거도 보완했습니다. 기존 코드와 가중치의 재사용 가능성을 조사한 뒤 데이터 검사, 학습과 평가 절차를 구성하고 새 모델을 웹앱에 연결했습니다.

## 이전 프로젝트와 후속 개발

| 구분 | 초기 acne-CV | 후속 acne-care |
|---|---|---|
| 개발 형태 | 5인 팀으로 개발했으며 모델링과 Flask 백엔드 등을 담당했습니다. | 혼자 데이터 정비부터 모델 실험과 웹앱 전체를 개발했습니다. |
| 사용자 흐름 | 사진을 업로드하고 얼굴 부위별 결과와 기록을 조회했습니다. | 촬영일·촬영 조건을 저장하고 여러 기록을 타임라인·그래프·리포트로 비교하도록 확장했습니다. |
| 모델과 평가 | KerasCV YOLOv8과 MediaPipe를 활용했습니다. | PyTorch 기반 YOLO11n으로 전환하고 라벨 보완·입력 크기·추가 증강·외부 데이터 추가 실험을 수행했습니다. |
| 웹 서비스 | Flask와 SQLite로 프로토타입을 구성했습니다. | FastAPI와 SQLite로 백엔드를 새로 구현하고 PC·휴대폰 화면과 기록 관리 기능을 개발했습니다. |

## 직접 기여

### 데이터 검사와 라벨 보완

기존 Kaggle 데이터의 Validation·Test에서 라벨 누락이 있는 이미지 26장을 수정했습니다. 부적합한 Validation 이미지 2장과 Train에 중복된 Test 이미지 1장을 제외해 dataset-v2를 구성했습니다.

외부 이미지 2,047장을 자동 검사하고 일부 라벨을 직접 검토·편집했습니다. 기존 분할은 유지하고 외부 이미지를 파일명과 이미지 유사도로 묶어 나눈 뒤, Train 2,256장·Validation 361장·Test 354장의 dataset-v3를 구성했습니다.

### 모델 학습과 비교 실험

YOLO11n의 입력 크기, 추가 증강과 외부 데이터 추가 효과를 비교했습니다. 입력 크기 832와 대비·회전·안전 크롭을 추가한 실험은 Validation F1을 개선하지 못해 채택하지 않았습니다. 최종 모델은 입력 크기 640과 기본 증강을 유지했습니다.

데이터 구성의 효과를 확인하기 위해 dataset-v2·v3 학습 모델의 탐지 기준 점수를 공통 Validation 361장에서 각각 선택하고, 동일 Test 354장에서 비교했습니다. 학습과 웹앱 실행을 분리해 사진 분석·기록 조회에는 학습 데이터나 학교 GPU 접속이 필요하지 않도록 구성했습니다.

### 웹앱과 기록 비교 기능

FastAPI에 사진 업로드·추론·기록 조회·메모 수정·삭제 API를 구현하고 SQLite와 로컬 사진 저장을 연결했습니다. 웹 화면에서는 PC·휴대폰에 맞춰 사진 업로드와 지원 브라우저의 촬영 기능, 탐지 상자 선택·확대와 원본 전환을 구현했습니다.

여러 기록을 촬영일순으로 정렬해 사진 타임라인과 탐지 개수 그래프로 비교하고, 사진·그래프·개수 차이·촬영 조건 설명을 모은 리포트를 구현했습니다. 리포트는 브라우저 인쇄와 PDF 저장을 지원합니다.

### 분석 조건의 기록과 비교

분석 결과에 모델 식별자, 가중치 확인값, 탐지 기준 점수와 입력 크기 등을 함께 저장했습니다. 기록 사이에 분석 설정이 달라지면 비교 화면에서 차이를 확인할 수 있도록 했습니다. 촬영 조건의 차이와 누락도 리포트 설명에 반영했습니다.

## 결과와 검증

다음은 2026년 11월 10일 acne-care 내부의 외부 데이터 추가 실험 결과입니다. 두 모델 모두 YOLO11n이며, 초기 acne-CV 모델과의 직접 비교 수치로 해석하지 않습니다.

| 동일 Test 354장 평가 | dataset-v2 학습 모델 | dataset-v3 학습 모델 |
|---|---:|---:|
| F1 | 0.422 | 0.536 |
| 사진당 개수 오차(Count MAE) | 2.282개 | 1.718개 |
| mAP50–95 | 0.150 | 0.217 |

F1은 정밀도와 재현율을 함께 보는 지표입니다. Count MAE는 정답 개수와 탐지 개수 차이의 절댓값을 평균한 수치이며 낮을수록 좋습니다. mAP50–95는 여러 상자 겹침 기준에서 측정한 탐지 성능이며 높을수록 좋습니다.

통합 Test에서는 개선됐지만 기존 Test 47장의 F1은 0.652에서 0.643으로 낮아졌습니다. 외부 데이터 라벨은 일부만 직접 검토했으며, 동일 인물이 여러 분할에 포함됐는지는 확인하지 못했습니다. 따라서 이 결과를 일반적인 피부 사진 전체의 성능으로 단정하지 않습니다.

서비스에서는 사진 분석, 기록 관리, 여러 기록 비교와 리포트를 하나의 웹앱으로 연결했습니다. 기능 구현과 모델 실험의 근거는 아래 원본 코드와 실험 기록에서 확인할 수 있습니다.

## 제약과 개선 방향

탐지 개수는 조명·촬영 거리·얼굴 방향과 사진에 보이는 피부 범위에 따라 달라질 수 있습니다. 의료 진단이나 피부의 호전·악화 판정을 제공하지 않으며, 시연 자료의 개수 변화도 실제 치료 효과를 뜻하지 않습니다.

로그인 없는 개인용 로컬 프로토타입입니다. 공개 서비스 배포와 사용자별 기록 분리는 별도 구현이 필요합니다. 데이터 측면에서는 외부 라벨 검토 범위를 넓히고 동일 인물의 분할 간 중복 여부를 검증할 필요가 있습니다.
